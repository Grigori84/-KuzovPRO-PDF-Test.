# Эксперимент с эфемерной подписью — 10.11.2026

Статус: исследование, не готово к интеграции или реальным документам.

Приватная тестовая Cloud Function с существующим сервисным аккаунтом `storage.uploader` получила эфемерные ключи по своему IAM-токену через API CreateEphemeral без постоянного S3-ключа. Ключи и подписанные ссылки не выводились и не сохранялись. Срок ключа запрошен 900 секунд.

Подписанная POST-форма с дополнительной session policy не загружала данные: Object Storage вернул 400 MaxMessageLengthExceeded при тестовых пределах 1024, 32768 и 33554432 байт. Причина не установлена. Тесты не доказывают, что Object Storage не поддерживает POST.

Подписанный PUT с эфемерным ключом без session policy, сформированный и использованный внутри функции для синтетической короткой строки с маркерами PDF, вернул 200. GET по подписи PUT вернул 403 SignatureDoesNotMatch, повторный PUT по той же ссылке вернул 200. Это не тест Android, полноценного PDF или прямой передачи с отдельного устройства; повторное использование может перезаписать staging-объект. Попытка PUT с session policy вернула 400 MalformedPolicy; причина не установлена, и факт выпуска ключа не подтверждает корректность политики.

После испытаний последняя версия функции возвращена к диагностике наличия токена, загрузка отключена; временный синтетический объект остался под staging/ на удаление жизненным циклом, выполнение очистки не подтверждено. Функция осталась приватной; роли и бакеты не менялись.

До интеграции: проверить ограничение размера на стороне Storage для прямой загрузки, подпись размера и хэша, истечение и полномочия на другие объекты, настоящий PDF с отдельного клиента, атомарную фиксацию проверенных байтов, SHA-256 и проверку PDF, предотвращение перезаписи и гонок, идемпотентность, отзыв, удаление staging, срок 60 дней, авторизацию владельца Android и фактические мобильные браузеры. Эфемерные ключи не отзываются отдельно до истечения срока; нельзя помещать их постоянные предшественники или универсальные учётные данные в APK.
