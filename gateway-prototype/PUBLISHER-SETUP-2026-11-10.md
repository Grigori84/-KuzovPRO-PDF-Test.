# Подготовка отдельного публикатора — 10.11.2026

Создан сервисный аккаунт `kuzovpro-pdf-publisher` (ajeto738mg37484p11qv), без ролей на каталог. Создана отдельная Cloud Function `kuzovpro-pdf-publish-test` (d4e8e6b0eostuume0994), приватная, Node.js 22, подключён новый аккаунт. Диагностическая версия успешно исполнилась, HTTP 200, `publication: disabled`.

Роли новому аккаунту пока не выданы. Предложенный начальный объём: `storage.viewer` на `kuzovpro-staging-test-84`, `storage.uploader` на `kuzovpro-pdf-test-84` и никаких ролей на каталог/облако/другие бакеты. Эти роли дают чтение закрытого бакета и запись/чтение публичного бакета; встроенное `storage.uploader` не позволяет удалять объекты, для отзыва требуется `storage.editor` или проверенная более узкая альтернатива. Пользователь согласовал `storage.editor` только на два упомянутых тестовых бакета при доказанной необходимости. Учитывать отдельную проверку разрешения на конкретное изменение доступа при работе через UI.

При попытке открыть «Назначить роли» на странице безопасности закрытого бакета консоль Yandex Cloud дважды завершилась ошибкой TypeError в UserRolesDialog, Error ID 8e860c88-667b-46f7-9463-1f7a5cada19d и 6a04be86-1827-4e78-85a1-1dd35947c90b. Изменений доступа не произведено. Bucket policy может ограничить субъект, префикс и операции, но учесть альтернативный доступ через ACL; существующие политики, ACL и публичный доступ не менять без анализа и подтверждения последствий.

Проверка публикации, SHA-256 через нового публикатора, просмотр, отзыв и повторный запрос пока не выполнены. Загрузчик и основной репозиторий не менялись. Обе функции приватные, публичная функция публикации не включена.
