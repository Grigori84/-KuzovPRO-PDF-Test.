# Проверка условного PUT — 10.11.2026

Исследовательский тест, не готов для реальных данных. Функция оставалась приватной; новые права не назначались. Использован эфемерный ключ, выпущенный через IAM, без дополнительной session policy. Ссылки и ключи не выводились.

Функция сгенерировала небольшой искусственный PDF-подобный документ с таблицей xref (346 байт), подписала URL PUT вместе с заголовками `content-length`, `content-md5`, `if-none-match: *` и произвела запросы сама. Фактическая валидность PDF внешним просмотрщиком и загрузка с отдельного клиента не проверялись.

| Проверка | Фактический ответ |
|---|---|
| Изменённый If-None-Match до загрузки | 403 SignatureDoesNotMatch |
| Первая запись | 200 |
| Повторная запись по той же ссылке и заголовкам | 412 PreconditionFailed |
| Изменён путь объекта | 403 SignatureDoesNotMatch |
| Ссылка с датой подписи на 10 минут в прошлом и сроком 120 секунд | 403 AccessDenied; причина могла включать время действия эфемерного ключа, повторить с реально истёкшей ссылкой |
| Изменено содержимое при сохранённом подписанном MD5 и размере | 400 BadDigest |
| Отправлены 10000 байт при подписанной длине 346 | 403 SignatureDoesNotMatch |

Предыдущая попытка отправить 33554433 байта из функции завершилась JobExecutionDiscarded без результатов, при 128 МиБ памяти и недоступных логах. Причина не подтверждена; проверка предела 32 МиБ и большого тела не выполнена. Подписывание точной длины не заменяет серверное правило выдачи разрешений только для длины 1..33554432 и испытаний его обхода, в том числе длинного потока и некорректного HTTP framing. Проверка конкурентных запросов и удаление объекта до истечения разрешения не выполнены; условие If-None-Match повторно позволит создание после удаления.

Официальная документация Yandex Cloud описывает `X-Amz-Copy-Source-If-Match`: несовпадающий ETag даёт 412; права чтения источника и записи назначения обязательны. Условное копирование, проверка SHA-256 скопированного файла, атомарность публикации, защита от гонок и отзыв не испытаны. Сначала копировать в приватное карантинное место, сверить хеш и потом безопасно публиковать; исключить публикацию до окончательной проверки и однозначно решить гонки. ETag сам по себе не является SHA-256.

Для повторяемой проверки отдельного клиента нужен безопасный канал передачи краткосрочной подписанной ссылки без раскрытия в чат, историю, логи или репозиторий; функция должна выдавать разрешение только после надёжной авторизации. После тестов активная версия функции возвращена к безопасной диагностике с upload disabled, 128 МиБ и таймаутом 30 секунд. Тестовые файлы находятся в staging; очистка жизненным циклом не подтверждена.
