# Проверка загрузки PDF отдельным клиентом — 10.11.2026

Статус: эксперимент, система не готова к реальным документам и интеграции.

Использовался существующий приватный Cloud Function и аккаунт staging uploader без добавления прав. Функция получала эфемерный ключ, подписывала конкретные PUT с Content-Length, Content-MD5 и If-None-Match: *; разрешения переданы отдельно запущенному клиенту в зашифрованном конверте RSA-OAEP/AES-GCM. Секреты, временные разрешения и реальные документы не записывались в репозиторий. Функция не передавала тело файла. Размеры и MD5 в экспериментальной версии были заранее заданы в коде, а не принимались из произвольного клиентского запроса. Проверка size > 33554432 при выпуске разрешений выполнена на одном заранее заданном значении; это ещё не полноценный проверенный API.

Тестовые PDF сгенерированы ReportLab, дополнены пробелами после EOF до целевого размера; pdfinfo распознал 32-МиБ вариант. Тесты выполнялись curl на отдельном облачном компьютере, не Android и не браузером, через сетевой прокси.

- 6 522 143 байта (~6,22 МиБ): 200.
- 33 554 432 байта (ровно 32 МиБ): 200.
- 33 554 433 байта: проверка в функции не выдала разрешение. Кроме того такой файл отправлен на адрес, подписанный на 33 554 432 байта: получен 403. Код ошибки тела не извлечён; отдельная причина ответа не установлена, поскольку объект уже существовал и имелся If-None-Match. Не считать это независимым доказательством механизма ограничения длины в Storage.
- Два одновременных PUT одного 6-МиБ файла: ответы 200 и 412. Следующий повтор: 412. Это один тест конкурентности, не доказательство для всех гонок.
- Пробный CORS OPTIONS с Origin https://example.com и запросом PUT для content-md5,if-none-match: 403. Другой конкретный origin и фактическая загрузка из браузера не проверены; настроек CORS не меняли. Для нативного Android CORS не применяется.
- Подмена тела и signed headers уже проверены в предыдущем документе; в данном прогоне не повторялись. Удаление объекта до истечения ссылки и реальное истечение ссылки не проверялись. Если объект удалить до истечения разрешения, If-None-Match снова может стать истинным; отложить удаление до истечения ссылки либо хранить и контролировать состояние на сервере.

Срок ссылки для эксперимента 600 секунд; эфемерный ключ 900 секунд. Настоящее истечение не проверено. POST-form content-length-range документирована Yandex, но ранее получена ошибка; причин не установлено. При PUT серверу выдачи требуется общая проверка целого размера 1..33554432, точная подписанная длина и Content-MD5, тесты некорректной длины и больших потоков, лимиты и авторизация. MD5 — контроль передачи, SHA-256 нужен отдельно; авторизация Android и хранение состояния не реализованы.

План публикации: ограниченные права отдельной функции чтения staging и записи карантина; чтение фиксированной версии или условного источника по ETag; серверный потоковый подсчёт SHA-256, проверка размера и разбор PDF с лимитами; копирование конкретной версии/по X-Amz-Copy-Source-If-Match в закрытый карантин; сверить SHA-256 копии; только после подтверждения публиковать конкретные проверенные байты с уникальным ключом и 60-дневным сроком; проверить отсутствия гонки публикации, неизменяемость, идемпотентность и отзыв. Публичное хранилище не использовать как карантин. ETag не считать SHA-256.

После тестов функция восстановлена в режим upload disabled и повторно запущена: 200, service_account_token_available=true. Публичный вызов не включался. Два тестовых объекта остаются в staging по правилу жизненного цикла, фактическое удаление не проверено. Основной репозиторий не менялся.
