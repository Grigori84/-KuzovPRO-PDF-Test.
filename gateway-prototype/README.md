# Защищённая загрузка сметы — прототип Cloud Functions

**Статус: исходники подготовлены, функция в облаке НЕ создавалась и НЕ проверялась.** Это отдельный проект, который не меняет приложение `Grigori84/KuzovPRO`.

## Что делает `index.js`

Приватная Yandex Cloud Function получает авторизованный `POST` с `{"operation":"begin-upload"}`, формирует криптостойкое 128-битное случайное имя `staging/<32 hex>.pdf` и возвращает **подписанную S3 POST-форму** на срок до 300 секунд. Размер PDF ограничен 32 МиБ серверной политикой формы. PDF передаётся приложением **напрямую в Object Storage**, без передачи тела файла через Cloud Functions.

Функция использует Node.js 22, переменные `STORAGE_BUCKET`, `STORAGE_ACCESS_KEY_ID`, `STORAGE_SECRET_ACCESS_KEY`, зависимости из `package.json`. Секреты только из Yandex Lockbox и только на стороне функции. Значения, токены, ключи или заполненные формы **не добавлять в GitHub и не присылать в чат**.

## Жёсткие условия безопасности

1. Функция **не должна быть публичной**. У вызова должен быть реальный Cloud IAM-механизм авторизации владельца; Android-клиентскую аутентификацию ещё предстоит разработать и проверить. Нельзя оставлять универсальный API-ключ внутри APK.
2. Сервисный аккаунт для начала должен иметь не более `storage.uploader` на **конкретном тестовом бакете**. Не выдавать `admin` или широкие права на весь каталог.
3. Это только первый шаг. **Не формировать клиентский URL на основе `staging/`** и не отправлять SMS после выдачи тикета.
4. Повторное использование подписанной формы в течение пяти минут может перезаписать временный объект. Для неизменяемых смет нужен отдельный `finalize`: сервер проверяет фактический файл, SHA-256 и размер, переносит проверенные байты в случайный окончательный ключ `estimates/<32hex>.pdf`, затем удаляет временную копию. При сбое переиспользует существующую запись операции, не создавая новые версии.
5. Для `staging/` потребуется **отдельное правило Lifecycle на 1 день** для уборки незавершённых пробных загрузок. Уже созданное правило `estimates/` → 60 дней не изменять.
6. Для немедленного отзыва / удаления нужна отдельная серверная операция с необходимыми правами. `storage.uploader` удалять объекты не может. Рассмотреть отдельный сервисный аккаунт для отзыва.
7. На уровне SMS и исторических PDF необходимо сохранять существующие неизменяемость, коды согласования и запрет на отправку до удаления старой публикации.

## Как испытать (после настройки Cloud Functions)

1. Приватная функция доступна только авторизованному владельцу. Анонимный вызов должен быть отвергнут на уровне облака.
2. Проверить, что правильный `POST` создаёт одноразовую форму только для `staging/`.
3. Файл `test_smeta.pdf` меньше 32 МиБ успешно загружается с тестового клиента. Попытка более 32 МиБ отклоняется самим Object Storage.
4. `GET` напрямую к функции не выдаёт тикет; ошибочный payload не выдаёт тикет.
5. После истечения 300 секунд загрузка по старой форме не проходит.
6. До завершения `finalize` клиентская SMS-ссылка не должна формироваться.
7. После будущего `finalize` сверить sha256, размер, открытие PDF.js и удаление через 60 дней.
