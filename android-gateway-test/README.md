# КузовPRO — тест шлюза

Самостоятельное небольшое приложение для Samsung с **Android 8.0/API 26 и выше**.
Идентификатор пакета: `ru.kuzovpro.gatewaytest`. Устанавливается отдельно от КузовPRO.
Исходный протокол: PR №1 тестового репозитория, commit
`54a7e6340847695c845b2560f25d07bbf99ef513`.

Адрес зафиксирован в коде:
`https://d5dfv1oa7vjlshd5ic71.4kscn31j.apigw.yandexcloud.net/pdf`.

## Что реализовано

- Создание ECDSA P-256 (`secp256r1`) в Android Keystore, `SHA256withECDSA`.
  Приложение не читает и не экспортирует закрытый ключ; аппаратная защита зависит
  от конкретного Samsung. StrongBox не требуется.
- Публичный ключ — стандартный Base64 без переносов, DER/SPKI; есть копирование.
  ID устройства — случайный `test_` + 32 hex, сохраняется локально. IMEI, серийный
  номер и Android ID не используются.
- «Без подписи»: POST с тем же синтетическим begin, без `x-kpro-*`.
- «Подписанный begin»: передаются только `operation`, размер синтетических байт
  и их MD5 в Base64. Синтетические байты: ASCII-строка
  `KuzovPRO gateway synthetic auth test v1` с одним LF в конце.
  Это не PDF; сервер проверяет PDF только на этапе publish, которого здесь нет.
- «Повторить запрос»: сохранённый в памяти последний подписанный begin/revoke,
  абсолютно те же байты тела и значения всех четырёх заголовков подписи. Новая
  подпись, timestamp и nonce не создаются. «Без подписи» не заменяет этот снимок.
- «Отозвать»: новый подписанный revoke текущего ID с новым случайным nonce.
  Успех — только HTTP 2xx, совпадающий ID и JSON boolean `revoked: true`.
- Выданный ID синхронно сохраняется через `SharedPreferences.commit()`, переживает
  закрытие процесса и перезагрузку. До подтверждённого отзыва следующий begin
  заблокирован. После отзыва ID остаётся виден до следующего успешного begin.
- Поворот экрана не перезапускает запрос. Повтор сохраняется при повороте, но
  после уничтожения процесса исчезает намеренно: временные подписи на диск не пишутся.
- Показываются HTTP-статус, допустимый серверный код ошибки, понятные ошибки DNS,
  TLS, соединения и таймаута. HTML и произвольный текст сервера не выводятся.

## Протокол подписи

`raw` — ровно UTF-8 байты, которые затем отправляются в POST.

```text
canonical = timestamp_seconds + "\n" + nonce_hex + "\n" + lowercase_hex(SHA256(raw))
signature = Base64(DER(SHA256withECDSA(private_key, UTF8(canonical))))
```

Заголовки: `x-kpro-device`, `x-kpro-time`, `x-kpro-nonce`, `x-kpro-signature`.
Timestamp — секунды Unix, nonce — 16 случайных байт / 32 строчных hex-символа.
Тело после подписания не сериализуется повторно.

## Сборка Codemagic только с телефона

Доступ к аккаунту Codemagic в этой задаче не предоставлен. YAML подготовлен для
ручного запуска; результаты фактической локальной сборки см. в `CHECKS.md`.

1. Откройте `https://codemagic.io` в Samsung Internet/Chrome и войдите через GitHub.
   При неудобном интерфейсе включите «Версия для ПК» в меню браузера.
2. Выберите **Add application**, GitHub, репозиторий
   **`Grigori84/-KuzovPRO-PDF-Test.`** — точка входит в имя. Разрешите доступ именно
   к тестовому репозиторию, если он ещё не доступен Codemagic.
3. Используйте конфигурацию **codemagic.yaml** из корня репозитория. Не создавайте
   конфигурацию Flutter. Android-проект находится в `android-gateway-test/`.
4. Нажмите **Start new build**, выберите ветку **`feat/android-gateway-test`** и workflow
   **`gateway-test-debug`** («КузовPRO — тест шлюза (debug APK)»), затем запустите сборку.
   Эта ветка включает код актуального PR №1; слияние PR №1 не требуется.
5. Дождитесь зелёного результата всех шагов. YAML использует Java 17, Node 22,
   Gradle Wrapper 8.9, AGP 8.7.3, Kotlin 2.0.21 и Android SDK 35. Владелец не
   устанавливает SDK на телефон. Codemagic может запросить принятие условий сервиса
   или доступную квоту минут для mac_mini_m2.
6. В завершённой сборке откройте **Artifacts** и скачайте **`app-debug.apk`**.
   Там же будут SHA-256, отчёт JVM-тестов и lint. APK инструментальных тестов
   компилируется для проверки, но не нужен для установки приложения.

Автоматических триггеров, деплоя, публикации APK и отправки в Google Play в YAML нет.
Секреты IAM/S3 и переменные Yandex Cloud для сборки не нужны. Фиктивные
`STAGING_BUCKET=offline-private` и `PUBLIC_BUCKET=offline-public` заданы только
для существующих офлайн-тестов сервера. В APK они не попадают, облако не вызывается.

## Установка на Samsung

1. Скачайте APK из результата этой задачи либо из Artifacts успешной сборки Codemagic.
2. Откройте файл через «Мои файлы → Загрузки». Если Android запросит разрешение,
   откройте «Настройки → Безопасность и конфиденциальность → Установка неизвестных
   приложений» и разрешите установку только тому браузеру или «Моим файлам»,
   через который открываете APK. Названия пунктов зависят от One UI.
3. Если «Автоблокировка» Samsung запрещает сторонние APK, учитывайте это ограничение
   в настройках устройства. После установки верните настройки защиты и разрешение
   источника в исходное состояние.
4. Нажмите «Установить», откройте **«КузовPRO — тест шлюза»**. Интернет — единственное
   разрешение, запросов доступа к файлам, контактам и SMS нет.

Debug APK из разных сред/новых сборок может быть подписан разными отладочными
сертификатами. Если обновление несовместимо по подписи, сначала отзовите ID и
удалите тестовый ключ, затем удалите старое тестовое приложение и установите новое.
Удаление приложения удаляет его ключ; новый экземпляр потребуется зарегистрировать
на сервере заново. Основное приложение КузовPRO не затрагивается.

## Проверка на телефоне

1. Включите автоматические дату и время: сервер допускает расхождение до 90 секунд.
2. Скопируйте ID устройства и публичный ключ. Для успешной авторизации эта пара
   должна уже находиться в `DEVICE_PUBLIC_KEYS_JSON` действующего сервера.
   Передавайте владельцу сервера только ID и публичный ключ. Регистрация ключа
   не выполняется приложением; эта работа не меняет настройки шлюза.
3. Нажмите **«Без подписи»**. При доступном и настроенном шлюзе ожидается
   `HTTP 401 · UNAUTHORIZED`. Если шлюз выключен, возможен
   `HTTP 503 · GATEWAY_DISABLED`: это реальный результат, а не ошибка подписи.
4. Нажмите **«Подписанный begin»**. Ожидается `HTTP 200` и сохранённый ID.
   Временный PUT URL игнорируется; самих синтетических байт/PDF приложение не загружает.
5. Сразу нажмите **«Повторить запрос»**. Если первый запрос прошёл авторизацию
   и его nonce был сохранён сервером, в пределах 90 секунд ожидается
   `HTTP 409 · REPLAYED_REQUEST`. После 90 секунд возможен `401 UNAUTHORIZED`.
   Если исходный запрос не прошёл авторизацию, повтор также может вернуть 401.
6. Закройте приложение, откройте снова: ID должен остаться, а повтор — стать
   недоступным после уничтожения процесса. Нажмите **«Отозвать»**: ожидается
   `HTTP 200`, «Отзыв ID подтверждён сервером и сохранён».
7. Можно сразу повторить revoke кнопкой **«Повторить запрос»** для проверки защиты
   от повтора: тот же ожидаемый `409 REPLAYED_REQUEST`.

При таймауте сервер мог принять запрос. Успех не показывается без подтверждения.
Если ответ begin потерян, сервер мог выдать ID, который телефон не получил;
replay вернёт 409 и не восстановит этот ID. В этом случае укажите владельцу сервера
тестовый ID устройства для проверки оставшихся записей. Приложение не утверждает,
что такой ID был отозван. Локальная ошибка сохранения известного ID показывается
отдельно вместе с ID; запишите его перед выходом.

## Удаление тестового ключа после испытаний

1. Сначала нажмите **«Отозвать»**, дождитесь подтверждения HTTP 200. Если сеть
   недоступна, сначала восстановите соединение; удаление ключа не заменяет revoke.
2. Запишите ID устройства для удаления серверной регистрации.
3. Нажмите **«Удалить тестовый ключ» → «Удалить»**. Удаляется только выделенный alias
   `kuzovpro-gateway-test-p256-v1` этого приложения в Android Keystore, локальный ID
   устройства, выданный ID и снимок для replay. При следующем запуске ключ не
   создастся сам; для нового испытания есть кнопка «Создать тестовый ключ».
4. Удалите запись этого ID из серверного списка разрешённых публичных ключей
   через владельца сервера. Это отдельно от удаления локального ключа.
5. Можно удалить тестовое приложение через «Настройки → Приложения».
   Обычное удаление приложения также удаляет его ключи Android Keystore.

## Разработка и проверки

```sh
cd simple-gateway
npm ci --ignore-scripts --no-audit --no-fund
STAGING_BUCKET=offline-private PUBLIC_BUCKET=offline-public npm test
cd ../android-gateway-test
./gradlew testDebugUnitTest lintDebug assembleDebug assembleDebugAndroidTest
```

Для сборки нужны JDK 17 (локальная проверка допускает JDK 21), SDK 35 и Node.js
для теста совместимости с `auth()` из актуального `simple-gateway/index.js`.
`local.properties` со строкой `sdk.dir=...` хранится только локально.

Инструментальный тест `DeviceKeyTest` проверяет создание, повторное чтение,
подписание, неэкспортируемость и удаление ключа под отдельным временным alias.
Для запуска на подключённом тестовом устройстве/эмуляторе:
`./gradlew connectedDebugAndroidTest`. Его компиляция не означает запуск на Samsung.

Сырые HTTP-ответы, подписи, private key, подписанные URL и исключения не логируются.
Ответ ограничен 16 КиБ. HTTP redirects отключены на каждом соединении. Backup и
перенос данных приложения выключены; URL загрузки и подписи на диск не сохраняются.
В коде приложения нет PUT, publish, выбора реальных файлов и облачных SDK.
