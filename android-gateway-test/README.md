# КузовPRO — тест шлюза · 0.2 PDF

Самостоятельное приложение `ru.kuzovpro.gatewaytest`, Android 8+/API 26.
Ветка `feat/android-gateway-test`, PR №2. Основной КузовPRO и серверные исходники
не изменяются. Используется протокол PR №1, commit `54a7e63`.

**Шлюз закреплён владельцем за `gateway-disabled`. Эта разработка не переключает
его и не выполняет живой цикл публикации. Отдельное разрешение на переключение —
только после установки нового APK.**

## Установка обновления только с Samsung

1. Скачайте `artifacts/kuzovpro-gateway-test-debug.apk` из этой ветки. Файл реально
   собран в Codex; контрольная сумма рядом, результаты — в `CHECKS.md`.
2. Откройте через «Мои файлы → Загрузки» и выберите обновление существующего
   «КузовPRO — тест шлюза». Версия — **0.2-pdf-test**, versionCode **2**.
3. Разрешите установку только используемому браузеру/«Моим файлам», если One UI
   запросит это. После установки верните разрешение источника в прежнее состояние.
4. Подпись готового APK проверена и совпадает с ранее выданным здесь APK 0.1.
   Обновление поверх него сохраняет Keystore-ключ и ID устройства; удалять старую
   версию не требуется. APK из другой среды Codemagic может иметь другую подпись.
   При конфликте подписи не удаляйте приложение с незавершённым циклом: удаление
   уничтожит ключ и локальное восстановление.
5. Проверьте прежние ID устройства/публичный ключ. Если ключ был удалён вручную,
   новый создаётся кнопкой и требует новой регистрации владельцем сервера.

## Что проверить сейчас, пока шлюз отключён

Нажмите **«Создать тестовый PDF (локально)»**, затем **«Посмотреть PDF локально»**.
Должна быть одна страница с крупным текстом **«КузовPRO — тест PDF»**.
Никакие клиентские файлы не выбираются: документ создаётся Android PdfDocument.
Проверьте размер/SHA-256 на экране, закройте и снова откройте приложение:
они должны сохраниться. Генерация, локальный просмотр и запуск приложения
не обращаются к шлюзу. Код не меняет настройки Yandex Cloud.

ID, оставшийся от теста авторизации 0.1, мигрирует отдельно: его можно отозвать,
но нельзя публиковать, поскольку старый искусственный набор не был PDF.
Подтверждённо отозванный старый ID позволяет создать новый локальный PDF.

## Полный цикл — после отдельного разрешения

У владельца сервера уже должна быть зарегистрирована пара ID устройства + DER/SPKI
публичный ключ. Автоматические дата и время обязательны; допуск подписи 90 секунд.

1. Подготовьте PDF локально. Нажмите **«Полный цикл: begin → PUT → publish»**
   и подтвердите начало теста. Приложение отправляет подписанный begin, сохраняет
   полученный ID, выполняет HTTPS PUT, проверяет HTTP и совпадение ETag с MD5,
   отправляет подписанный publish и скачивает опубликованный PDF для сверки
   размера и SHA-256. Каждый этап записывается до следующего сетевого действия.
2. Ожидаемый результат: этап «опубликован», полученный ID и подтверждение совпадения
   скачанного PDF. Нажмите **«Открыть PDF.js в Samsung Internet»**. Сначала запускается
   Samsung Internet; если его нет — другой установленный браузер. Открывается только
   проверенная публичная ссылка PDF.js из ответа publish, не PUT-ссылка.
3. Нажмите **«Отозвать»**. Новый подписанный revoke использует прежний ID и новый nonce.
   Успех — HTTP 2xx, совпадающий ID и boolean `revoked: true`. Затем автоматически
   проверяется прямой адрес объекта: HTTP **403/404** подтверждает недоступность.
4. Нажмите **«Проверить документ без кэша»** ещё раз. GET содержит новый cache-buster,
   `Cache-Control: no-cache, no-store`, `Pragma: no-cache`, redirects запрещены.
   HTTP 200 после revoke — ошибка проверки; 3xx/5xx/таймаут тоже не доказывают отзыв.
5. Уже скачанную копию в памяти браузера отозвать невозможно. Проверка приложения
   обращается к самому объекту, а не к HTML-странице PDF.js, которая останется доступной.

Доступны и отдельные кнопки begin, PUT и publish для пошагового испытания.
«Без подписи» по-прежнему проверяет отказ авторизации. «Повторить запрос» отправляет
ровно тот же последний подписанный POST, без новой подписи/nonce/timestamp; PUT эта
кнопка не повторяет. Если nonce уже использован, до истечения 90 секунд ожидается 409.

## Обрыв, потерянные ответы и восстановление

Приложение не продолжает сетевой цикл автоматически при запуске и не создаёт второй
begin после неизвестного результата. Повторные нажатия сериализуются одним worker;
поворот экрана не запускает вторую операцию. Для продолжения существующего цикла
используется **«Продолжить publish того же ID»**, с новым nonce и прежними PDF/ID/SHA-256.

| Ситуация | Действие |
| --- | --- |
| begin вернул явный `401 UNAUTHORIZED` или `503 GATEWAY_DISABLED` | ID не выдан; локальный PDF сохранён. Повторный begin только по нажатию пользователя |
| Ответ begin потерян или `503 GATEWAY_UNAVAILABLE` | `BEGIN_UNKNOWN`, новый begin и удаление ключа заблокированы. API не умеет искать потерянный ID; владельцу сервера нужна проверка записей по ID устройства. Не очищайте данные приложения |
| ID получен, но его локальное сохранение не удалось | ID показан из памяти; PUT и дальнейшая сеть заблокированы. Запишите ID и восстановите локальное хранение |
| Ответ PUT потерян | Сохраняются исходные байты и ID; проверьте publish того же ID. Сервер сам сверяет размер, SHA-256 и PDF |
| Повтор PUT дал 409/412 | Объект мог уже сохраниться; перезаписи нет (`If-None-Match: *`). Продолжите publish того же ID |
| Процесс закрыт/PUT-ссылка истекла | PUT URL намеренно не сохраняется. Можно проверить publish прежнего ID или отозвать его. Новый begin автоматически не выполняется |
| Publish вернул `UPLOADED_PDF_MISSING` | Полная загрузка не подтверждена. Можно отозвать прежний ID; после подтверждённого закрытия начать отдельный новый тест вручную |
| Ответ успешного publish потерян | Повтор publish с теми же байтами и ID идемпотентен; сервер вернёт прежнюю публикацию |
| `PUBLICATION_IN_PROGRESS` / `PUBLISHING_IN_PROGRESS_RETRY` | Не считать успехом и не создавать новый ID. Повторить позже; зависшее серверное `publishing` может требовать ручного восстановления по регламенту PR №1 |
| Ответ revoke потерян | Повторить revoke того же ID с новым nonce. Publish после неизвестного revoke заблокирован |
| Revoke подтверждён, но GET не завершён | Повторить только проверку документа. Новый тест и удаление ключа после попытки publish доступны лишь после подтверждения недоступности |

При восстановлении `*_PENDING` превращается в соответствующее `*_UNKNOWN`.
Просроченный точный replay с HTTP 401 не сбрасывает неизвестный begin в «готово».
После ошибки чтения/записи состояния приложение не удаляет его и блокирует новый цикл.

## Хранение и безопасность

- ECDSA P-256 в Android Keystore, alias `kuzovpro-gateway-test-p256-v1` сохранён от 0.1.
  Закрытый ключ не экспортируется. Публичный ключ — Base64 DER/SPKI без переносов.
- Атомарный файл `noBackupFilesDir/pdf-cycle-v2.json`: ID, этап, точные исходные
  PDF-байты в Base64, размер, SHA-256, публичная ссылка PDF.js и результаты проверок.
  При чтении SHA-256/размер пересчитываются; PDF не генерируется заново для старого ID.
- `AtomicFile` завершает запись с fsync перед сетью. Снимок подписанного POST и
  билет PUT живут только в памяти процесса. Подписи, nonce и подписанные URL в JSON
  не попадают. Локальный preview-файл также находится в noBackup и удаляется после чтения.
- Backup и перенос данных выключены; Android Keystore не экспортируется в backup.
- В APK нет IAM-токенов, S3-ключей, облачных SDK, аналитики, выбора клиентских файлов.
  Сырые ответы, временные URL и сообщения/stack traces исключений не логируются.
- HTTPS PUT разрешён только на `storage.yandexcloud.net/<bucket>/staging/<id>.pdf`.
  Проверяются подписанные Content-Type/Length/MD5/If-None-Match и их наличие в
  `X-Amz-SignedHeaders`; лишние заголовки/redirects отклоняются. Length отправляется
  fixed-length streaming и точно совпадает с сохранёнными байтами.

Фиксированный gateway:
`https://d5dfv1oa7vjlshd5ic71.4kscn31j.apigw.yandexcloud.net/pdf`.
Публичный GET соответствует существующему `client.html`:
`https://storage.yandexcloud.net/kuzovpro-pdf-test-84/estimates/<id>.pdf`.
Ни настройки сервера, ни viewer, ни бакеты приложение не меняет.

Подпись прежняя:
`Base64(DER(SHA256withECDSA(UTF8(time + "\n" + nonce + "\n" + hex(SHA256(raw))))))`.
Подписываются ровно UTF-8 байты, которые затем отправляются.

## Удаление тестового ключа

1. Дождитесь подтверждения revoke и недоступности документа после попытки publish.
2. Запишите ID устройства и нажмите «Удалить тестовый ключ → Удалить».
   При неизвестном результате эта кнопка недоступна, чтобы не потерять возможность восстановления.
3. Удалите запись этого устройства из серверного списка ключей через владельца сервера.
   Локальное удаление ключа не заменяет серверный revoke.
4. PDF и подтверждённое состояние остаются для проверки; новый ключ сам не создаётся.
   Для нового испытания есть кнопки создания ключа и нового локального PDF.
   Удаление приложения уничтожит и локальные данные, и его Keystore-ключи.

## Сборка Codemagic с телефона

В этой задаче сборка выполнялась в Codex. Доступа к аккаунту Codemagic нет;
утверждения о запуске Codemagic нет.

1. В `https://codemagic.io` войдите через GitHub, выберите Add application.
2. Репозиторий **`Grigori84/-KuzovPRO-PDF-Test.`** — точка входит в имя.
3. Используйте корневой `codemagic.yaml`; ветка **`feat/android-gateway-test`**,
   workflow **`gateway-test-debug`**. На телефоне SDK устанавливать не нужно.
4. После зелёной сборки скачайте **`app-debug.apk`** из Artifacts. Там же SHA-256,
   JVM-отчёт и lint. Готовый APK в Git автоматически этой сборкой не обновляется.

YAML: Java 17, Node 22, SDK 35/Build Tools 35.0.0, Gradle 8.9/AGP 8.7.3/Kotlin 2.0.21.
Автотриггеров и секции publishing/deploy нет; тесты не вызывают облако.
Перед JVM-тестами нужен `npm ci` в `simple-gateway`: два теста вызывают настоящий
серверный workflow и PDF-парсер через локальный stdin/stdout без HTTP.

```sh
cd simple-gateway
npm ci --ignore-scripts --no-audit --no-fund
STAGING_BUCKET=offline-private PUBLIC_BUCKET=offline-public npm test
cd ../android-gateway-test
./gradlew testDebugUnitTest lintDebug assembleDebug assembleDebugAndroidTest
# Только при доступном Android-устройстве/эмуляторе, без живого шлюза:
./gradlew connectedDebugAndroidTest
```

Инструментальные тесты используют отдельные временные alias/файлы, не сетевые запросы
и не действующее состояние пользователя. Полный список файлов — `FILES.md`.
