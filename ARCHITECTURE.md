# КузовPRO — схема выдачи PDF-смет (проверочная архитектура, 10.11.2026)

## Подтверждено на устройстве владельца

- Yandex Object Storage, бакет `kuzovpro-pdf-test-84`.
- Синтетический PDF 6,22 МиБ, 5 страниц: отображены первая и последняя страницы через PDF.js на Samsung.
- Статическая страница GitHub Pages использует HTTPS и читает Object Storage напрямую, без API Яндекс.Диска.
- iPhone Safari, реальная смета из APK, долгосрочная доступность и отзыв ссылок **не проверены**.
- Репозиторий `Grigori84/KuzovPRO` не изменялся.

## Клиентская ссылка

Тест: `https://grigori84.github.io/-KuzovPRO-PDF-Test./client.html#demo`.

Для новых PDF предполагается объект `estimates/<id>.pdf`, где `id` — 16 байт из криптостойкого случайного генератора Android (например, `SecureRandom`), записанные в 32 шестнадцатеричных символа. Не использовать имя клиента, телефон, госномер, трёхзначный код согласования или порядковый номер заказа.

Формат публичной SMS-ссылки: `https://grigori84.github.io/-KuzovPRO-PDF-Test./client.html#id=<32-hex>`.

Фрагмент `#id=...` не отправляется серверу GitHub при загрузке HTML и не должен содержать каких-либо персональных данных. Страница конструирует URL `https://storage.yandexcloud.net/kuzovpro-pdf-test-84/estimates/<id>.pdf` и загружает PDF напрямую. Это **ссылка-ключ доступа**: любой получатель ссылки может читать PDF, а CORS не является механизмом ограничения чтения. На текущей фазе не размещать реальные клиентские документы.

## Удаление по сроку

Установить правило Lifecycle в бакете:
- Включено.
- Описание: `Delete estimate copies after 60 days`.
- Префикс: `estimates/`.
- Expiration (удаление), количество дней: `60`.
- Не включать versioning без отдельной политики удаления старых версий.
- Правило применимо **к дате загрузки объекта**, а не к дате отправки SMS. Поэтому публикацию и загрузку надо синхронизировать, не перезаписывать тот же объект.
- Обработка выполняется по суточному расписанию; точной минуты удаления не обещать.
- Тестовый файл в корне бакета правилом с префиксом `estimates/` не затрагивается.
- Исходный PDF на Яндекс.Диске очищается существующим механизмом Android; жизненный цикл Object Storage **не удаляет** файлы с Диска.

## Безопасность и архитектура загрузки (не реализовано)

APK не должен хранить долгоживущий секрет S3 / сервисного аккаунта.
Предпочтительная схема:
1. Подтвердить аутентифицированную личность мастера на небольшом серверном endpoint (механизм авторизации предстоит проработать отдельно).
2. Backend назначает / утверждает объект `estimates/<id>.pdf`; выдаёт ограниченное во времени разрешение на загрузку (pre-signed PUT либо POST с ограничением 32 МиБ и типом application/pdf).
3. КузовPRO выгружает PDF **напрямую в Object Storage**, а не через функции. Контролируются размер, целостность и защита от повторной перезаписи.
4. После успешного подтверждения загрузки формируется клиентская ссылка, сохраняемая в неизменяемой версии сметы; далее SMS и логика согласования — как сейчас.
5. При отзыве выполняется авторизованное удаление объекта Object Storage с повторами и проверкой результата; отдельно отзыв ссылки/удаление файла на Яндекс.Диске. Не считать отзыв завершённым до успешной очистки обоих источников.
6. По истечении 60 суток Lifecycle — резервный механизм удаления **копии** в Object Storage.

Не публиковать рабочие файлы до проверки модели доступа и требований обработки персональных данных.

## Не смешивать

- 3-значный код: только для согласования; никогда не идентификатор URL.
- 60-дневный Android cleanup: удаляет исходную копию с Диска, зависит от телефона.
- 60-дневный Lifecycle: независимо от телефона удаляет объект из Object Storage, с суточной задержкой.
- Копия Object Storage не заменяет исходный PDF, его версии и правила согласования.
