# КузовPRO — упрощённая выдача PDF (черновой прототип)

**Цель:** кнопка «PDF» → загрузка → одна SMS-ссылка → уже проверенный на Samsung просмотрщик \`client.html\`. Один бакет, одна функция. Не менять основной Android-репозиторий до испытаний. **Состояние: код подготовлен, развёртывание и сквозной тест НЕ выполнены.**

## Почему не прямой PUT в публичную папку

До окончания загрузки и проверки объект не должен быть доступен клиенту. Поэтому в **одном и том же бакете** две папки:
- \`staging/<128-bit-id>.pdf\` — закрытая; загрузка по подписанному PUT, 1 день на автоматическую очистку;
- \`estimates/<128-bit-id>.pdf\` — публичное чтение **только по известной ссылке**, 60 дней на автоматическую очистку.

**Одна** Cloud Function (\`index.handler\`) выполняет \`begin\`, \`publish\`, \`revoke\`. Нет второго бакета, нет второй функции, нет API Яндекс.Диска. Текущий просмотрщик GitHub Pages/\`PDF.js\` остаётся.

## Схема работы

1. На Android формируется PDF и вычисляются MD5 (Base64), SHA-256 (hex) и размер.
2. Приложение, подписывая запрос своим **Android Keystore P-256** ключом, вызывает \`begin\`. Функция выдаёт одноразовое случайное имя и PUT URL на 5 минут. Постоянных ключей Yandex Cloud в APK **нет**.
3. Android делает PUT байтов прямо в Object Storage с точными заголовками из ответа функции. Никакой передачи файла через функцию.
4. Подписанный запрос \`publish\` содержит \`id\`, \`bytes\`, \`sha256\`. Функция проверяет фактическую длину, начало/конец PDF, SHA-256, затем копирует конкретную версию из закрытой папки в открытую и удаляет промежуточную копию. Только после подтверждения возвращает ссылку на \`client.html#id=...\`.
5. Приложение сохраняет \`id\` с **неизменяемой версией сметы** и предлагает отправить ссылку по SMS.
6. \`revoke\` удаляет оба объекта, затем проверяет отсутствие публичного объекта. Lifecycle отдельно удаляет объекты по сроку.

Повтор \`publish\` после успешно завершённой публикации возвращает тот же адрес, если размер и SHA-256 совпадают. **Не включать versioning без отдельного управления версиями.**

## Безопасность: однократное привязывание смартфона

Функция может принимать анонимные HTTPS-вызовы только потому, что **сама** отказывает в операции без правильной цифровой подписи зарегистрированного устройства. Публичность Cloud Function — это не публичные права записи в бакет.

При первом запуске Android создаёт неэкспортируемый закрытый ключ в Android Keystore; публичный ключ в DER/SPKI кодируется Base64. В настройках функции один раз вручную указывается:
\`DEVICE_PUBLIC_KEYS_JSON={"phone1":"<base64-spki-public-key>"}\`
Это **не секрет**. Отзыв доступа к телефону — удалить его запись из конфигурации функции и выпустить новую версию.

Каждый HTTPS POST имеет заголовки:
- \`x-kpro-device: phone1\`
- \`x-kpro-time: <Unix-time-seconds>\`
- \`x-kpro-nonce: <32 hex, fresh random>\`
- \`x-kpro-signature: <base64-DER-ECDSA>\`

Подписываются UTF-8 байты строки:
\`\`\`
<Unix-time-seconds>\n<nonce-hex>\n<SHA256-hex-of-raw-JSON-body>
\`\`\`
Алгоритм \`SHA256withECDSA\`, кривая P-256, подпись DER. Окно времени ±90 сек; HTTPS обязателен. На сервере нет отдельной БД пользователей и постоянного ключа приложения. **До использования с реальными клиентами дополнительно проверить защиту от повторов, лимиты вызовов и процедуру потери телефона.**

## API

Все запросы: \`POST\`, \`Content-Type: application/json\` и четыре заголовка подписи.

**Begin:**
\`\`\`json
{"operation":"begin","bytes":6522143,"md5_base64":"<MD5-binary-base64>"}
\`\`\`
Ответ: \`{"id":"...","upload_url":"https://...","headers":{"Content-Type":"application/pdf","Content-MD5":"...","Content-Length":"6522143","If-None-Match":"*"},"expires_seconds":300}\`.

**Android PUT**: послать *ровно* PDF-байты и headers из ответа на \`upload_url\`; успех — HTTP 200/2xx. Не отправлять PUT URL в SMS, логи или аналитику.

**Publish:** \`{"operation":"publish","id":"<32hex>","bytes":6522143,"sha256":"<64hex>"}\`
Ответ (после подтверждения): \`{"id":"...","url":"https://grigori84.github.io/-KuzovPRO-PDF-Test./client.html#id=...","already_published":false}\`.

**Revoke:** \`{"operation":"revoke","id":"<32hex>"}\`
Ответ: \`{"id":"...","revoked":true}\`. На ошибках приложение НЕ должно объявлять ссылку отозванной.

## Конфигурация Object Storage — инструкция, ничего здесь автоматически не меняется

1. Целевой тестовый бакет: \`kuzovpro-pdf-test-84\`. Сначала проверить существующие ACL, policy, публичность. **Сейчас этот тестовый бакет используется рабочим \`#demo\`; не ломать его текущие настройки без проверки.**
2. Общий публичный доступ на запись **запрещён**. Общий публичный доступ на чтение для всего бакета **выключен**; bucket policy разрешает анонимный \`s3:GetObject\` только на \`estimates/*\`. Чтобы прежний \`#demo\` не сломался, дополнительно разрешить тестовый \`KuzovPRO_large_test_6.2MB.pdf\`. Анонимные \`GET staging/*\` и \`ListBucket\` должны возвращать 403. Исключить обход через ACL.
3. На сервисный аккаунт единственной функции нужны **бакет-ограниченные** права чтения, записи, копирования и удаления. **Не выдавать** права на весь каталог. В настройках Yandex Cloud ранее была ошибка \`UserRolesDialog\`; пока не разрешена, **не обходить её расширенными правами**.
4. CORS бакета для \`https://grigori84.github.io\`: GET, HEAD (дополнительная загрузка с Android нативная, CORS ей не нужен). Исходный PDF читается браузером из Object Storage.
5. Lifecycle: \`staging/\` → 1 день; \`estimates/\` → 60 дней. Это срок от загрузки/создания объекта, точная минута удаления не гарантируется. Корневой демо-PDF отдельно.
6. Node.js 22, entrypoint \`index.handler\`, переменные: \`STORAGE_BUCKET\`, \`VIEWER_URL\`, \`DEVICE_PUBLIC_KEYS_JSON\`, \`STORAGE_ACCESS_KEY_ID\`, \`STORAGE_SECRET_ACCESS_KEY\`, \`GATEWAY_ENABLED\`. Секреты доступа — только в защищённой конфигурации/Lockbox, **никогда в GitHub или APK**. По умолчанию функция отключена: \`GATEWAY_ENABLED\` должен быть ровно \`true\`.
7. Если текущая функция остаётся приватной IAM-only, обычный APK без отдельной IAM-аутентификации её не вызовет. Для схемы с Android-подписями придётся разрешить HTTPS-вызов функции, **но только после** теста проверки подписей и оценки лимитов вызовов. Не включать пока.

## Контрольные испытания ДО реальной сметы

- Неподписанный или неверно подписанный запрос \`begin/publish/revoke\` → 401; функция отключена без \`GATEWAY_ENABLED=true\`.
- Изменение \`bytes\`, MD5, PDF или \`If-None-Match\`, повтор PUT, повтор \`publish\`, 32 МиБ и 32 МиБ+1 байт.
- Анонимное чтение \`staging/*\` запрещено, \`estimates/*\` доступно только с известным длинным ID, список бакета запрещён.
- Только после подтверждённого \`publish\` ссылка открывается в Chrome и Samsung Internet; после \`revoke\` открытие не работает; после 60 дней удаление выполняется вне зависимости от смартфона.
- Протестировать телефон из РФ, реальную PDF-смету с кириллицей и фото, iPhone Safari, повторное открытие, мобильный интернет и ошибки сети.
- Проверить подписанные PUT-заголовки конкретно на Yandex Object Storage: реализация **не была запущена или испытана**.

**Не переносить в основной \`Grigori84/KuzovPRO\`, пока эти испытания не пройдены.**
