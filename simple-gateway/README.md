# КузовPRO — минимальный PDF-шлюз (тестовый PR)

**Статус: кодовый прототип, НЕ развёрнут в Yandex Cloud и НЕ готов для настоящих клиентских данных.**

## Итоговая схема

**Одна Cloud Function, два уже существующих бакета, работающий просмотрщик PDF.js.**

- Закрытый бакет `kuzovpro-staging-test-84`: `staging/<id>.pdf` — временные файлы (Lifecycle 1 день), `control/<id>.json` — записи состояний, `auth-nonces/<device>/<nonce>` — защита от повторных запросов.
- Публичный бакет `kuzovpro-pdf-test-84`: `estimates/<id>.pdf` — готовые PDF (Lifecycle 60 дней).
- Просмотрщик: `https://grigori84.github.io/-KuzovPRO-PDF-Test./client.html#id=<32hex>`. Для `#demo` текущий доступ сохранить.
- PDF передаётся Android **прямо в закрытый бакет** по подписанному PUT. Тело загружаемого PDF не проходит через Cloud Function. При публикации функция однократно читает до 10 МиБ, валидирует и пишет подтверждённый файл в публичный бакет.

**Лимит PDF — 10 МиБ (10 485 760 байт).**

## Что изменено после аудита Work

1. Появился файл `workflow.js` — серверная машина состояний с условной записью (compare-and-swap) через S3 `If-Match` и `If-None-Match`.
2. `begin` атомарно создаёт неизменяемый случайный ID и запись `issued`, затем выдаёт краткосрочный PUT (300 сек), подписанный для конкретных заголовков и размера.
3. `publish` сравнивает размер и SHA-256, выполняет разбор структуры PDF библиотекой `pdf-lib`, атомарно переключает `issued → publishing`, выполняет **PutObject с If-None-Match: *** в публичном бакете, подтверждает объект и фиксирует `published`. **CopyObject больше не используется.**
4. `revoke` отклоняется, пока статус `publishing`; затем атомарно переключает состояние в `revoking`, удаляет оба файла, проверяет отсутствие публичного объекта, фиксирует `revoked` и **никогда не удаляет контрольную запись**.
5. Даже если старый подписанный PUT вновь загрузит временный файл после удаления, `revoked` не позволит опубликовать тот же ID.
6. Запросы Android подписаны ключом P-256 из Android Keystore, на сервере известны только зарегистрированные публичные ключи. Каждый запрос включает timestamp и nonce; использованный nonce записывается в закрытый бакет атомарным PutObject. Старая подпись уже не может повторить операцию.
7. Код загружает PDF до 10 МиБ, проверяет маркеры PDF и открывает документ в `pdf-lib` без игнорирования шифрования. Это **структурная проверка**, а не доказательство отсутствия любого вредоносного содержимого.
8. `GATEWAY_ENABLED` по умолчанию выключен; основной `Grigori84/KuzovPRO` не менялся.

## Состояния и сбои

```
issued -> publishing -> published -> revoking -> revoked
   |                                        ^
   +---------------> revoking -------------+
```

- Публикация после `revoking/revoked` возвращает HTTP 410. Ссылка не восстанавливается.
- Повтор после успешно опубликованной сметы возвращает тот же URL, только если объект ещё существует и совпадают размер и SHA-256.
- Если PutObject завершился, а ответ потерялся, следующий вызов `publish` может распознать существующий объект и перевести `publishing → published`.
- **Если процесс умер после захвата `publishing`, но до записи файла, состояние остаётся блокирующим.** Это безопаснее, чем разрешить гонку с удалением. Требуется отдельный ручной регламент восстановления после проверки отсутствия активных вызовов; автоматический безопасный таймаут пока НЕ реализован. Кнопка отзыва не должна показывать успех при 409.
- Не отключать и не очищать `control/` без процедуры миграции. Lifecycle на `control/` **не настраивать на 1 день**: запись должна прожить как минимум весь период возможного существования публикации и её отзыва. На этапе испытаний сохранять бессрочно.
- Для `auth-nonces/` следует отдельно настроить Lifecycle 1 день (окно подписи 90 секунд), иначе такие объекты будут копиться.

## Авторизация Android (протокол)

Зарегистрировать один раз публичный ключ DER/SPKI смартфона, Base64, в серверной переменной `DEVICE_PUBLIC_KEYS_JSON`, например `{"phone1":"<Base64-public-key>"}`. Приватный ключ остаётся в Android Keystore.

Для каждого `POST`:
- `x-kpro-device`: зарегистрированное имя устройства;
- `x-kpro-time`: Unix timestamp в секундах;
- `x-kpro-nonce`: 16 случайных байт, представленных 32 hex-символами;
- `x-kpro-signature`: Base64 DER-ECDSA (`SHA256withECDSA`).

Подписываем UTF-8 строку `<time>\n<nonce>\n<SHA256-hex-raw-JSON-body>`. Окно времени ±90 секунд. Для блокировки повтора используется условная запись nonce в Object Storage.

**Важно:** технически веб-адрес Cloud Function должен быть доступен приложению, а аутентификация обеспечивается кодом функции. Открывать публичный вызов до испытаний, лимитов запросов, защиты конфигурации и проверки модели угроз **запрещено**.

## API

`POST` + четыре заголовка подписи, Content-Type: `application/json`.

| Операция | Тело | Успех |
|---|---|---|
| `begin` | `{"operation":"begin","bytes":6522143,"md5_base64":"<Base64-MD5>"}` | `id`, `upload_url`, `headers`, `expires_seconds:300` |
| `publish` | `{"operation":"publish","id":"<32hex>","bytes":6522143,"sha256":"<64hex>"}` | `id`, `url`, `already_published` |
| `revoke` | `{"operation":"revoke","id":"<32hex>"}` | `id`, `revoked:true` |

Приложение должно **сохранять ID и неизменяемую версию сметы сразу после `begin`**, чтобы восстанавливаться после обрыва сети; в Android reference добавлен обязательный callback `persistIssued(id)` перед передачей PDF; реальная реализация постоянного локального хранилища остаётся задачей интеграции в приложение. Отправлять SMS **только после ответа `publish` 200**.

- Runtime Node.js 22, точка входа `index.handler`, память/таймаут — испытать на реальном 10-МиБ PDF.
- `STAGING_BUCKET=kuzovpro-staging-test-84`

- `GATEWAY_ENABLED` отсутствует или `false` до всех проверок; `true` только после согласованного тестового запуска.

Роли сервисного аккаунта нужны только на конкретных двух бакетах. **Не давать admin на каталог или облако.** Не создавать новые бакеты или вторую функцию.

1. Выполнить `cd simple-gateway && npm install && npm test`; тесты пока не запускались в стандартном Node.js с настоящими зависимостями. Независимо выполнены 8 тестов логики `workflow.js` с имитацией Object Storage.
2. Проверить условный `PutObject` с `IfMatch` и `IfNoneMatch` в Yandex Cloud, включая конкурентные запросы и поведение ETag.
3. Проверить, что подписанный PUT **в действительности подписывает все четыре заголовка** (Content-Type, Content-Length, Content-MD5, If-None-Match); код отказывает в выдаче билета, если подпись их не охватывает. Ранние эксперименты на Яндексе не доказывают этот новый вариант.
4. Проверить, что просмотрщик открывает публикацию, демо `#demo` продолжает работать; удаление и отзыв делают файл недоступным даже после повторных запросов.

7. Нужны безопасные права из Yandex Cloud. Ошибка `UserRolesDialog` и тикет поддержки `TS416610986` пока не разрешены.
8. Lifecycle в публичном бакете `estimates/` = 60 дней; закрытый `staging/` = 1 день. Фактическое удаление по Lifecycle нельзя считать проверенным заранее.
