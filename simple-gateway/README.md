# КузовPRO — PDF-шлюз: минимальная схема, аудит 10 ноября 2026 года

**Статус: черновой прототип, НЕ готов к запуску с документами клиентов.** Операции `publish` и `revoke` в коде намеренно возвращают HTTP 501, пока не решены проблемы безопасности.

## Архитектурное решение после аудита Work

**Оставить существующие два бакета и использовать одну Cloud Function.** Это проще в настройке, чем переделывать существующий бакет с публичным чтением всех объектов.

- `kuzovpro-staging-test-84` — уже закрытый; временные `staging/<id>.pdf`, существующая очистка через 1 день.
- `kuzovpro-pdf-test-84` — уже публично читаемый; готовые `estimates/<id>.pdf`, существующая очистка через 60 дней.
- Уже проверенный на Samsung просмотрщик `client.html#id=<32 hex>` без изменений. Для `#demo` оставить текущую конфигурацию CORS и доступ к тестовому файлу.
- Одной Cloud Function выдать короткий тикет загрузки, затем подтвердить публикацию и обработать отзыв. Сама передача PDF выполняется напрямую между Android и закрытым бакетом.
- Предельный размер PDF **10 МиБ** (`10 * 1024 * 1024` байт). Код исправлен с прежних 32 МиБ.

**При этом новый Cloud Function / доступ к бакетам НЕ настроены. Приложение Grigori84/KuzovPRO НЕ изменено.**

## Как должна работать кнопка

1. Android формирует PDF неизменяемой версии сметы, вычисляет длину, MD5 и SHA-256.
2. Подписывает запрос `begin` ключом в Android Keystore, функция возвращает краткосрочный подписанный PUT с непредсказуемым `id`.
3. Android отправляет PDF напрямую в закрытый `staging` (не в функцию) с проверяемыми размером, MD5 и условием `If-None-Match: *`.
4. Только после окончания и серверной проверки PDF вызывается `publish` и появляется постоянная ссылка на браузерный просмотрщик. Временная копия удаляется.
5. `revoke` должен гарантированно делать PDF недоступным, не позволяя повторно опубликовать тот же `id`. Публикации и отзывы должны быть устойчивы к повторам, сбоям сети и конкурентным вызовам.

## Главные блокирующие проблемы

1. **Неизменяемость результата.** Операция S3 `CopyObject` с `CopySourceIfMatch` проверяет *источник*, но не блокирует перезапись *назначения*. Предварительный `HeadObject` не защищает от гонки. Требуется доказанная защита от повторной записи, например потоковая `PutObject` с `If-None-Match: *` из одной функции после проверки байтов; проверить работу в Yandex Cloud, включая два конкурентных вызова. Существующий `publish` — не использовать.
2. **Отзыв.** Сначала серверная отметка отзыва/запрет повторной публикации (с сохраняемой записью и атомарным разрешением гонки), затем удаление публичного объекта. Даже после ошибки/повторного вызова старая ссылка не должна снова заработать. Существующий `revoke` — не использовать.
3. **Подтверждение PDF.** Текущая проверка проверяет сигнатуру, маркер EOF, размер и SHA-256, **но не полную структуру PDF**. Так как источник — локальный генератор смет доверенного приложения, решить по модели угроз, нужна ли более глубокая проверка (и с каким лимитом ресурсов); не называть текущую проверку полной.
4. **Авторизация.** Android Keystore P-256 — прототип. До публичного вызова функции нужны тесты привязки смартфона, защита от повторов `nonce`, отказ в доступе после отвязки, лимиты/троттлинг и сценарий восстановления после потери телефона. Не включать `All users` без этих мер.
5. **IAM.** Из-за ошибки `UserRolesDialog` права функции на чтение staging и запись/удаление в публичном бакете не выданы. Нужны минимальные права только к этим бакетам. Не добавлять полномочия на каталог/облако; дождаться безопасного пути из обращения поддержки `TS416610986`.
6. **Проверки.** Прогнать Node.js тесты (`npm install && npm test`) и сквозные тесты на синтетических файлах (10 МиБ, 10 МиБ + 1, повторы и конкурентные вызовы, отзыв, Android, PDF.js, Lifecycle). Сейчас не выполнены.

## Настройки функции (только для будущих синтетических тестов)

- Node.js 22, entrypoint `index.handler`.
- `STAGING_BUCKET=kuzovpro-staging-test-84`.
- `PUBLIC_BUCKET=kuzovpro-pdf-test-84`.
- `VIEWER_URL=https://grigori84.github.io/-KuzovPRO-PDF-Test./client.html`.
- `DEVICE_PUBLIC_KEYS_JSON` — зарегистрированные публичные ключи устройств, не пароли.
- `STORAGE_ACCESS_KEY_ID`, `STORAGE_SECRET_ACCESS_KEY` — только защищённое серверное хранилище; не добавлять в исходный код, APK, историю чата, логи.
- `GATEWAY_ENABLED` отсутствует либо равно `false` по умолчанию. Только специальный тестовый прогон может установить `true` после проверки контролей и согласования.

Существующие бакеты и текущую функцию **не удалять**. PR не сливать до проведения испытаний и осознанного решения блокирующих вопросов.
