# Испытание внутри приватной функции — без внешнего IAM-токена

**Статус: новый тестовый обработчик не развёрнут и не испытан в Yandex Cloud.** Он создан для устранения тайм-аута при передаче подписанного PUT URL из браузерной среды Work в другой тестовый процесс.

Файл: `selftest.js`. Точка входа временной версии: `selftest.handler`.

## Принцип

Вызов выполняется через авторизованную вкладку **«Тестирование»** существующей приватной функции. Один запуск внутри самой Cloud Function получает эфемерные S3-ключи сервисного аккаунта, вызывает уже существующие `workflow.begin`, делает реальный HTTPS PUT подписанного URL, проверяет объект по SHA-256. При отдельном выборе выполняет публикацию и анонимный GET. Внешний скрипт, которому нужен отдельный IAM-токен для вызова функции, **не используется**.

**Это тест облачного хранилища и workflow, но не тест внешнего подписанного Android-вызова функции.** Авторизация Android ранее проверялась отдельным тестом 401/200, реальную интеграцию Android нужно проверить после.

## Подготовка

1. Сохранить текущую отключённую приватную версию `d4eofaqsan7ipqhcfr17` для отката (актуальность версии перепроверить в консоли).
2. Прочитать и сверить `selftest.js` из PR №1, добавить как новый текстовый файл в редактор уже существующей функции **без ZIP**. Не переписывать `index.js`, `workflow.js`, `ephemeral.js`.
3. Создать новую приватную тестовую версию той же функции. Только для неё: `entrypoint=selftest.handler`, `SELFTEST_ENABLED=true`, `GATEWAY_ENABLED=false`, `STAGING_BUCKET=kuzovpro-staging-test-84`, `PUBLIC_BUCKET=kuzovpro-pdf-test-84`, `VIEWER_URL=https://grigori84.github.io/-KuzovPRO-PDF-Test./client.html`, сервисный аккаунт `kuzovpro-pdf-publisher`, Node.js 22 и достаточно времени выполнения. Новый/постоянный S3-ключ **не нужен**. Не открывать функцию публично.
4. Проверить, что обновление кода произошло без ошибок. Если редактор требует отклонённый ZIP либо отсутствует подтверждение сохранения, остановиться.

## Шаг A — только загрузка

В приватной вкладке «Тестирование» передать:

```json
{"operation":"upload"}
```

Ожидаемый JSON: `result=PASS`, `operation=upload-only`, `put_status=200` (или другой 2xx, если Yandex так отвечает), `sha256_match=true`, `revoked=true`, `staging_deleted=true`.

По окончании этот режим удаляет синтетический объект и оставляет в закрытом хранилище контрольную запись отзыва. При ошибке нужно сохранить только код ошибки, этап и ID для безопасной ручной очистки. **Не публиковать PDF и не печатать PUT URL.**

## Шаг B — публикация, только после успеха A

```json
{"operation":"publish"}
```

Этот режим делает синтетический PDF, begin → PUT → publish → анонимный GET и сверку SHA-256. При успехе возвращает `id` и `viewer_url`, который можно открыть для проверки на смартфоне. **PDF остаётся публичным до отзыва**.

## Шаг C — отзыв после просмотра

```json
{"operation":"revoke","id":"<id-из-шага-B>"}
```

Проверяет удаление публичного PDF, анонимное открытие (403/404), запрет повторной публикации (410) и повторный отзыв. Контрольную запись `control/<id>.json` сохраняет.

## Завершение

Создать или активировать новую версию с `index.handler` и `GATEWAY_ENABLED=false`, `SELFTEST_ENABLED=false`. Внешний вызов функции оставить закрытым. Контроль: 503 `GATEWAY_DISABLED`. Не удалять бакеты, роли и файлы `control/`; не использовать клиентские данные.

## Важные ограничения

- По мере действующей пятиминутной подписанной ссылки сервер выполняет PUT немедленно — не передаёт ссылку между инструментами.
- Тест может выявить несовместимость подписанных HTTP-заголовков/условной записи. При ошибке вернуть точный статус, не пытаться автоматически отключать проверки.
- После неоднозначного сбоя в `publishing` **не удалять или переопубликовывать объект наугад**. Действует ранее согласованный режим ручного разбора.
- Если в текущей версии функции отсутствуют нужные файлы или зависимости, не заменять их невалидными примерами. Сообщить, что обнаружено.
- Тест из внутренней функции **не подтверждает работу Android-клиента на мобильной сети**, его проверять отдельно.
