# Проверка прав публикатора — 10.11.2026

Консоль: `kuzovpro-pdf-publisher` имеет bucket-scoped `storage.editor` на обоих тестовых бакетах; прежний `kuzovpro-staging-uploader` сохраняет `storage.uploader` на закрытом бакете. Приватная Node.js 22 диагностическая версия от публикатора получила временный ключ CreateEphemeral HTTP 200 (все поля присутствуют; секреты не выводились). Объектные запросы выполнялись IAM-токеном, не временным ключом.

В каждом из бакетов отдельно создан случайный искусственный текстовый объект, не реальные данные. Получены: условный PUT If-None-Match `*` — 200; повторный PUT — 412; GET — 200, содержимое совпало; PUT If-Match с неверным ETag — 412; с правильным ETag — 200; DELETE — 204; последующее чтение отсутствующего объекта — 403 или 404. Наблюдение однократное: CAS при одновременных запросах не проверен.

Временные диагностические объекты удалены функцией. Восстановлена приватная диагностическая версия функции, таймаут 3 сек, проверен ответ HTTP 200 `publication: disabled`. Настройки бакетов и права не изменяли. Это не запуск PR, не PDF, не проверка signed PUT от публикатора и не сквозное испытание. Логи консоли были недоступны в ограниченном режиме работы платформы.
